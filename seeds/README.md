# Seeds

These are hand-written seed programs, one feature area per folder. The folder name sets the area
used in `typediff` statistics.

Each program:
- targets a typing feature ty claims to support;
- runs under **CPython 3.13**, so the runtime oracle works;
- calls everything it defines;
- marks lines a spec-conformant checker should reject with `# expect-error: …`. Lines that would
  crash at runtime are wrapped in `try/except`. Two seeds raise on purpose (marked in their
  headers) to give typediff a runtime oracle.

```bash
TYPEDIFF_LLM=null typediff --python-version 3.13 seeds seeds/          # judge all seeds (~1 min)
typediff --llm ... --python-version 3.13 generate --from-seeds seeds/self_classmethods --n 5 --out-dir runs/gen
python scripts/harvest_seeds.py                                         # + programs from upstream test suites (see below)
```

`seeds/harvested/` is generated by `scripts/harvest_seeds.py` and is not committed.

## Status on ty 0.0.84 / mypy 2.4.0 (first run)

| seed | result |
|---|---|
| `self_classmethods/self_param_inherited.py` | Reported as ty#4656, closed as **intended** (display bug: ty#4673). Regression seed for the `Self` rules: lands in REVIEW / is dismissed by KB `TY-SELF-UPPER-BOUND` after the desugar probe |
| `self_classmethods/self_classmethod_param.py` | Same design question through a classmethod and `tuple[Self, int]`; not a confirmed bug |
| `self_classmethods/self_runtime_witness.py` | Same pattern plus a runtime `AttributeError` witness; if it only crashes via `Self`-typed state, ty is unsound there, otherwise the call is the intended behaviour |
| `generics_variance/constrained_typevar.py` | Known upstream: ty#1090 (open) |
| `typeddict/readonly_notrequired.py` | `Unpack` extra keyword: ty#4212 (closed, intended for open TypedDicts) |
| `constructors_metaclasses/new_returns_other.py` | mypy reveals the class where `__new__`/metaclass return another type (CPython disagrees). Candidate, probably known |
| everything else | Agree, documented differences, or in review. See `typediff triage` |

## Harvested sources (`scripts/harvest_seeds.py --sources ...`)

| source | repo path | programs kept | notes |
|---|---|---|---|
| `conformance` | python/typing `conformance/tests` | 130 | spec-backed; errors marked `# E` |
| `ty` | astral-sh/ruff mdtest `*.md` | 3,509 | whole multi-file documents are skipped |
| `mypy` | python/mypy `test-data/unit/check-*.test` | 1,210 | normally run against fake stubs; here, real typeshed |
| `pyright` | microsoft/pyright `tests/samples/*.py` | 969 of 1,366 | written for pyright; many are intentionally invalid; `# pyright:` directives are ignored by mypy and ty |
| `typeshed` | python/typeshed `stdlib/@tests/test_cases` | 56 of 74 | `assert_type` checks that mypy and pyright agree on; **not meant to be executed** |

Measured on ty 0.0.84 / mypy 2.4.0, no LLM, about 1.5 s per program:

- `typeshed` (all 56): 84 findings in 8 patterns. About 30 are `runtime_miss` with "strong" runtime evidence that is
  harness noise: lines marked `# type: ignore` that are wrong on purpose, and stub-generic classes such as
  `zip[...]` that are not subscriptable at runtime. Start with the `only_ty type-assertion-failure` and
  `only_mypy assert-type` patterns.
- `pyright` (every 6th file, 160 programs): 295 findings in 118 patterns.

Try one source at a time, for example:

```bash
python scripts/harvest_seeds.py --sources typeshed,pyright --out seeds/harvested/lib
TYPEDIFF_LLM=null typediff --python-version 3.13 --no-pyright --no-reduce --out runs/typeshed seeds seeds/harvested/lib --iterations 60
typediff triage runs/typeshed --top 15 --details
```
