## 2. Option (b): small `kind: "crash"` extension, WARRANTED (scope fixed)

Nine of the fourteen filed issues are crashes/hangs, and (a)/(c) would leave all of them "unrepresentable", so later runs would show variants as new CONFIRMED findings. The extension is about 60 lines and changes nothing for existing findings:

- **Schema** (document in `_doc`): an `entries` item with `"kind": "crash"` and fields `tool` (mypy|ty|pyright), `signature` (regex, `re.fullmatch` against `Crash.signature`), `requires` (name in a new `_CRASH_REQUIRES` table; mandatory for every crash entry so none can match on tool+signature alone), `dismissal` (`DUPLICATE`), `stance`, `url`, `note`, `id`. No `codes`/`message`.
- **New module `typediff/crash_upstream.py`**: `load(path=PATH) -> list[dict]` (entries with kind crash), `_CRASH_REQUIRES: dict[str, Callable[[ast.Module], bool]]` (pure functions of the parsed source), `match_crash(source: str, tool: str, signature: str, path=PATH) -> dict | None` (first entry whose tool equals, signature regex fullmatches, and requires returns True; `SyntaxError` -> `None`; any exception inside a requires function -> `None`).
- **kb.py**: in `_upstream_entries()` add `if e["kind"] == "crash": continue` before `K(...)`. Nothing else in kb.py changes for crashes.
- **priors.py**: no change needed (`_matches` gates on `d.kind`, and crash findings call it with `d=None`). Confirm by test.
- **pipeline.py** (`_judge` loop, right after `f.signature = sig`, before `apply_prior_cap`): if `f.symptom == Symptom.CRASH`, call `match_crash(state.source, f.faulty_tool, f.signature)`; on a hit set `f.tier = Tier.DISMISSED`, `f.dismissal = Dismissal(e["dismissal"])`, append `f"DUPLICATE of {e['url']} ({e['id']}): {e['note']}"` to `f.review_notes`, and `continue` (mirrors the existing dataset-duplicate branch, so no reduction runs). `Symptom` import already available from `.models`. Only `rules.crash_findings` output with symptom CRASH is affected; `abnormal_exit` findings (symptom None, tier REVIEW) and all discrepancy findings take the old path.
- **Bounding tests** (tests/test_upstream_day3.py): (i) a crash finding with no matching entry is untouched (tier CONFIRMED); (ii) an `abnormal_exit` finding is never dismissed; (iii) a discrepancy finding path is unchanged (existing tests stay green); (iv) a crash entry does not appear in `kb.ENTRIES` (`UPSTREAM-TY-4882` not in `kb.BY_ID`) and `kb` import does not raise.
