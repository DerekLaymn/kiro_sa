### view 4899
OPEN Abort (memory blowup) or panic with a Callable[P, T]-annotated self in __init__ and a ParamSpec __call__
### Summary

### Summary

A class whose `__init__` annotates `self` as `Callable[P, T]`, combined with a `__call__` that is also typed over `Callable[P, T]` and takes an extra parameter, makes ty either run out of memory and abort or panic, depending on whether `__call__` is a classmethod.

Case 1, `@classmethod` (memory grows to 3 GB in about 5 seconds, then abort):

```py
import typing

T = typing.TypeVar("T")
P = typing.ParamSpec("P")


class User:
    def __init__(self: typing.Callable[P, T], *args: P.args, **kwargs: P.kwargs) -> None: ...

    @classmethod
    def __call__(cls: typing.Callable[P, T], x: int, *args: P.args, **kwargs: P.kwargs) -> T: ...


User()
```

```console
memory allocation of 1290096 bytes failed
timeout: the monitored command dumped core
```

Case 2, plain method:

```py
import typing

T = typing.TypeVar("T")
P = typing.ParamSpec("P")


class User:
    def __init__(self: typing.Callable[P, T], *args: P.args, **kwargs: P.kwargs) -> None: ...

    def __call__(self: typing.Callable[P, T], x: int, *args: P.args, **kwargs: P.kwargs) -> T: ...


User()
```

```console
fatal[panic] Panicked at .../salsa-0.28.5/src/function/execute.rs:751:9 when checking `case.py`: `when_constraint_set_assignable_to_owned_impl(Id(3681)): execute: too many cycle iterations`
```

Without the extra `x: int` parameter, or with only one of the two methods, ty finishes normally. The code is unusual, but it is a crash that ends the whole check. The same query name appears in closed #4222, #4337 and #4362. The original shape of Case 1 came from pyright#9148, where pyright accepts it.

**Expected:** no abort or panic. A diagnostic about the `self` annotation, or normal checking, would be fine.
