[ty] Model try exception flow with operation checkpoints | MERGED merged 2026-08-12T21:11:49Z
## Summary

Previously, we treated every definition inside a `try` block as a possible exception point, allowing handlers to observe states that could never occur:

```py
def may_raise(value: object) -> None: ...

state = 0
try:
    may_raise(state := 1)
except:
    reveal_type(state)
    # Before: Literal[0, 1]
    # After: Literal[1]
```

We now record exception checkpoints immediately before operations that can raise, after evaluating their operands. This includes calls, imports, name lookups, attribute access, operators, iteration, and other potentially raising operations.

(This is based on Carl's draft: #27221.)
