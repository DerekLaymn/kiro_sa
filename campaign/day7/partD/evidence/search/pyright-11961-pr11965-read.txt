=================== microsoft/pyright#11961
Crash (RangeError: Maximum call stack size exceeded) when a constructor method is annotated with its own class and the class is instantiated | OPEN | created 2026-11-02T07:35:36Z
**Describe the bug**

Pyright's command-line tool exits with status 2 and prints `RangeError: Maximum call stack size exceeded` when a class declares `__new__` or `__init__` (or a metaclass `__call__`) with a type that refers back to the same class, and the class is then instantiated.

Expected behavior: a normal diagnostic or no diagnostic, not an internal error.

Steps to reproduce: save any of the code samples below as `case.py` and run `pyright --pythonversion 3.13 case.py`.

The recursion runs `validateConstructorArgs` -> `validateNewAndInitMethods` -> `validateNewMethod` -> `validateArgTypesWithExpectedType` -> `validateConstructorArgs`, with no cycle guard (frames in `constructors.ts` lines 133, 176/177, 263, 427). Raising Node's stack size does not avoid the crash — it exhausts the stack and segfaults instead — so this is unbounded recursion, not merely a deep stack.

Each sample is valid at runtime (it runs under CPython without error). Removing the instantiation call, or annotating the constructor with a *different* class, avoids the crash. This reproduces on every released version tried (1.1.300 through 1.1.414), so it is long-standing rather than a recent regression.

**Code or Screenshots**

Each sample crashes on its own.

`__init__` annotated as its own class:

```python
class C:
    __init__: type["C"]

C()
```

`__new__` annotated as its own class:

```python
class A:
    __new__: type["A"]

A()
```

Metaclass `__call__` annotated as the instance class:

```python
class Meta(type):
    __call__: type["C"]

class C(metaclass=Meta): ...

C()
```

Output (all three):

```
An internal error occurred while type checking file "case.py": RangeError: Maximum call stack size exceeded
    at ... pyright-internal/src/analyzer/typeEvaluator.ts:23484:36
    at ... pyright-internal/src/analyzer/constructors.ts:427:34   (validateNewMethod)
    at ... constructors.ts:263:31
    at ... constructors.ts:176:36
    at ... constructors.ts:133:29   (validateConstructorArgs)
Error performing analysis: RangeError: Maximum call stack size exceeded
```

Controls that do not crash (same pyright version): `reveal_type(C.__init__)` without the `C()` call, and `class C: __init__: type[D]` where `D` is a different class.

**VS Code extension or command-line**

Command-line tool. pyright 1.1.414 (current npm `pyright@latest` and PyPI `pyright==1.1.414`); also reproduced on 1.1.300, 1.1.340, 1.1.380, 1.1.400, 1.1.410, and 1.1.413. Node v24.19.0, Linux.

=================== PR microsoft/pyright#11965
Prevent recursion through class-valued constructor methods | OPEN | created 2026-11-02T17:58:13Z
Fixed a bug in constructor validation when `__init__`, `__new__`, or a metaclass `__call__` is annotated with a class that leads back to the same constructor. This addresses #11961.

Constructor helpers forward the same arguments back through call validation without preserving its recursion counter. Track active constructor validations per evaluator and stop a repeated class/call/argument-list combination, with stack cleanup in `finally`. Fresh argument lists remain eligible for ordinary reentrant expression evaluation.

The regression sample covers all three reported variants, mutually recursive constructors, normal class-valued constructor annotations (including an invalid argument), and nested same-class calls. It also preserves the incompatible metaclass override diagnostic.
