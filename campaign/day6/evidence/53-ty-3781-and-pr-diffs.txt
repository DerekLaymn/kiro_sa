######## ty#3781
Flag non-hashable objects as error in `set`/`dict`
OPEN created 2026-06-16T19:05:06Z closed null
https://github.com/astral-sh/ty/issues/3781
### Summary

`ty` does not flag when non-hashable objects are inserted into `set` or `dict` which causes runtime errors. Below is an example with `set`.

Working example with a hashable object.

[Playground Link](https://play.ty.dev/cfccd0e2-986c-47a2-bfff-15bc3d74cef3)

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class HashableObject:
    content: str

obj = HashableObject("content")
print({obj})
```

Failing example with a non-hashable object where it fails during runtime:

[Playground Link](https://play.ty.dev/f38c32dd-5de4-4e90-bca2-5d49f0e73408)

```python
from dataclasses import dataclass

@dataclass
class NonHashableObject:
    content: str

obj = NonHashableObject("content")
print({obj})
```

runtime error:

```text
Failed to run Python script: PythonError: Traceback (most recent call last):
  File "/lib/python313.zip/_pyodide/_base.py", line 523, in eval_code
    .run(globals, locals)
     ~~~^^^^^^^^^^^^^^^^^
  File "/lib/python313.zip/_pyodide/_base.py", line 357, in run
    coroutine = eval(self.code, globals, locals)
  File "main.py", line 8, in <module>
    print({obj})
          ^^^^^
TypeError: unhashable type: 'NonHashableObject'
```
