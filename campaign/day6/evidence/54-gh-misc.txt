[ty] Preserve non-final types in Hashable unions MERGED 2026-06-17T11:44:37Z
## Summary

In https://github.com/astral-sh/ty/issues/1162#issuecomment-4343373191, we decided to stop simplifying `Hashable | C` to `Hashable` when `C` is non-final. A subclass can disable hashing even when its base class satisfies `Hashable`, so the existing normalization can discard a meaningful union arm:

```python
from collections.abc import Hashable, Sequence

def f(value: Hashable | Sequence[Hashable]) -> None:
    ...
```

This recognizes the standard-library protocol through both `typing.Hashable` and `collections.abc.Hashable`, and preserves the non-final arm while retaining the existing simplification for final classes and `object`.

This PR uses a relatively narrow / conservative model for determining hashability; https://github.com/astral-sh/ruff/pull/26040 is more expansive, but I think it deserves to be reviewed separately.

Closes https://github.com/astral-sh/ty/issues/1162.

false positive: tuples of Hashable-bounded type variables rejected as Hashable OPEN
### Summary

`ty` rejects `tuple[T, T]` as `Hashable` when `T` is bounded by `Hashable`. It also rejects the inferred constructor call below

```python
from collections.abc import Hashable

class Box[T: Hashable]:
    def __init__(self, value: T) -> None:
        self.value = value

def inferred[S: Hashable, A: Hashable](s: S, a: A) -> Box[tuple[S, A]]:
    return Box((s, a))  # invalid-argument-type

def explicit[S: Hashable, A: Hashable](s: S, a: A) -> Box[tuple[S, A]]:
    # accepted, the explicit constructor specialization seems to be a workaround for the first error
    return Box[tuple[S, A]]((s, a))  

def generic[T: Hashable](value: tuple[T, T]) -> Hashable:
    return value  # invalid-return-type

def concrete(value: tuple[Hashable, Hashable]) -> Hashable:
    return value  # accepted
```

### Summary

ty 0.0.86 reports `invalid-attribute-override` when a subclass defines `__hash__` after a dataclass base sets `__hash__ = None`. Python permits this, and ty 0.0.84 accepts it.

https://play.ty.dev/87be762f-a8a2-4770-b58f-879f24a24fcf
 
```python
from dataclasses import dataclass

@dataclass
class Base:
    value: int

class Child(Base):
    def __hash__(self) -> int:
        return hash(self.value)
```
